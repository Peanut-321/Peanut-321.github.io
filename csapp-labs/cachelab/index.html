2. RAM：主存是什么？

RAM 是 Random-Access Memory，随机访问存储器。这里的“随机访问”不是指乱访问，而是指访问任意地址的时间大致差不多。

  • SRAM：快、贵、不需要刷新，常用来做 Cache。
  • DRAM：慢一些、便宜、需要刷新，常用来做主存。

6. Cache 的本质

Cache 是一个小而快的地方，用来临时保存大而慢的地方的一部分数据。

CPU 访问某个地址时，会先检查 Cache：

  • 如果数据在 Cache 里，就是 cache hit，可以很快拿到。
  • 如果数据不在 Cache 里，就是 cache miss，需要去下一层存储里拿。

Cache 拿数据时通常不是只拿一个变量，而是按块搬运。比如访问 a[0] 时，Cache 可能把下面这些数据一起搬进来：

7. 三种 Cache Miss

  • Cold miss：第一次访问某个块，Cache 里肯定没有。
  • Capacity miss：正在使用的数据太多，Cache 放不下，只能不断替换。
  • Conflict miss：Cache 总容量够，但几个数据刚好被映射到同一个位置，于是互相挤掉。

8. Working Set

Working set 指的是程序在某一小段时间里正在频繁使用的数据集合。

如果 working set 能放进 Cache，程序通常会比较快；如果 working set 比 Cache 大，程序就容易频繁 miss，速度会明显下降。

1.1 Cache Line：valid bit、tag、block data

每一条Cache不止数据本身：

  • valid bit: 这条line现在有没有有效数据
  • tag: line中存的是内存的那一块
  • block data: 真正缓存的数据

为什么需要 valid bit？
刚运行时，cache里面可能是空的，如果只有 valid bit，CPU看到某个tag匹配，也不知道这条line中东西是否有效。因此判断hit时必须满足：

1.3 地址拆分：tag、set index、block offset

Cache 读一个地址时，会把这个地址直接拆成三段：

这三段不是三个新的变量，而是从同一个地址里切出来的不同 bit 段。

  • block offset：从地址里直接切出来的低位，表示“我要的字节，在这个 block 里排第几个”。例如一个 block 是 64 字节，就需要 6 个 bit 表示 0 ~ 63 的位置。
  • set index：从地址里直接切出来的中间位，直接当索引用，不需要比较。它规定了“这个地址必须去第几号 set 里查”。
  • tag：从地址里直接切出来的高位，不能直接当索引用，而是要和目标 set 里当前实际存放的几个 tag 逐一比较。只有 tag 对上，并且 valid bit 为 1，才说明“这个 set 里现在存的，正好是我要的那块内存”。否则就是 cache miss。
