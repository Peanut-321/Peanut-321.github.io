1. SRCNN 网络结构与计算分析

PS 端先通过 Bicubic（双三次插值）将低分辨率图像放大到目标尺寸，PL 端接收形状为 1×255×255 的单通道图像，再通过 SRCNN 的三层卷积改善放大后的模糊细节。

Bicubic 根据原图中已有的像素，对放大后新增位置的颜色或亮度进行插值估计。SRCNN 则利用训练得到的卷积权重进一步重建细节，网络输入和输出的空间尺寸均为 255×255。

层 作用 计算特点
Conv1：9×9，1→64 提取局部特征 每个输出通道的每个输出像素需要 1×9×9 = 81 次 MAC
Conv2：1×1，64→32 混合、映射特征通道 对同一位置的 64 个通道加权求和，每个输出元素需要 64 次 MAC
Conv3：5×5，32→1 重建最终图像 汇总 32 个通道的 5×5 邻域，每个输出像素需要 32×5×5 = 800 次 MAC

Conv2 的 1×1 卷积只读取当前空间位置的特征，不直接访问相邻像素。不过，这些特征已经由 Conv1 的 9×9 卷积提取，因此仍包含邻域信息。

与之前的 RoCC 卷积加速器项目不同，本项目采用 replicate-edge padding 处理边界：越界坐标被限制到最近的有效边缘像素，而不是补零。Conv1 和 Conv3 的 padding 半径分别为 4 和 2，使三层卷积都保持相同的空间尺寸。

当前卷积采用 cross-correlation（互相关）形式，计算时不翻转 kernel，而是将输入窗口与对应位置的权重逐项相乘并累加。

数据布局采用以下约定：

  • 激活张量：CHW，即 [channel][row][column]。
  • 权重张量：OIHW，即 [output-channel][input-channel][kernel-row][kernel-column]。

CHW 将每个通道的像素按行连续存储，便于逐行读取并使用 line buffer 缓存历史行。OIHW 则将同一输出通道对应的各输入通道权重连续存储，便于按输出通道组织计算。例如，Conv3 每个输入通道的 5×5 权重先展开为 25 个连续元素，再依次排列 32 个输入通道，共 800 个权重。

对于一帧 255×255 输入，三层的精确 MAC 数及其占比如下：

  • Conv1：337,089,600 MAC，约 64.5%
  • Conv2：133,171,200 MAC，约 25.5%
  • Conv3：52,020,000 MAC，约 10.0%
  • 总计：522,280,800 MAC

Conv1 占据约 64.5% 的计算量，是吞吐优化的主要目标；Conv3 每个输出像素需要累加 800 项，对累加器位宽和数值精度的要求更高。

另一个关键瓶颈是中间特征图（feature map）的存储与传输。按每个元素 32 bit 计算，Conv1 和 Conv2 的输出分别约为 15.88 MiB 和 7.94 MiB。若每层都将结果写回 DDR，再由下一层读入，会产生大量数据传输并消耗内存带宽。因此，后续 HLS 设计计划采用 line buffer、sliding window 和 DATAFLOW，让 Conv1→Conv2→Conv3 的中间数据尽量通过 PL 内的 FIFO 传递，减少 DDR 读写。
